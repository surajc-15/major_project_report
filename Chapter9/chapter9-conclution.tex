\chapter{Conclusion}
%========================================================

The proposed work successfully established a scalable and privacy-preserving federated graph-learning framework for intelligent Trade-Based Money Laundering detection across distributed institutional environments. The developed framework integrated heterogeneous graph construction, federated Hybrid HGNN--LSTM analytical inference, Apache Kafka-based transaction streaming, PostgreSQL-backed compliance orchestration, and regulator-facing monitoring synchronization within a unified operational architecture. Experimental evaluation demonstrated stable fraud-classification capability, reliable federated convergence behavior, and effective distributed synchronization across heterogeneous institutional transaction environments. The deployed framework achieved Fraud-class Precision values approaching $0.98$ while maintaining stable Recall characteristics during federated analytical inference workflows. Concurrent scalability evaluation additionally demonstrated stable dashboard retrieval latency near $156$--$162$ ms and controlled fraud-filtering response latency near $148$--$159$ ms during increasing institutional monitoring workloads. The overall analytical and operational outcomes validated the suitability of the proposed framework for scalable, real-time, and privacy-aware TBML detection across distributed institutional compliance ecosystems.

%========================================================
\section{Limitations}
%========================================================

Although the framework performed well during testing, a few practical limitations remain. The current evaluation still depends mostly on synthetically enriched transaction data, since verified real-world TBML datasets are difficult to access. As a result, some newer laundering tactics, cross-border irregularities, and more subtle trade-manipulation patterns may not appear as clearly as they would in live institutional data.

The federated learning pipeline also introduces communication overhead whenever model updates are exchanged and aggregated across participating institutions. That overhead is manageable at the current scale, but it can grow as more banks join the system or as the model is trained on larger transaction graphs. Likewise, very large heterogeneous graphs can increase the cost of multi-hop traversal and distributed inference.

The present implementation is focused on detection, monitoring, and compliance notification. It can flag suspicious activity and support regulator-side review, but it does not yet carry out direct operational actions such as transaction blocking, account freezing, document locking, or automated compliance-trigger execution. Those functions would need deeper integration with core banking systems and institution-level authorization workflows.

%========================================================
\section{Future Scope}
%========================================================

There are several clear ways to extend the framework into a more production-ready financial crime monitoring system. A useful next step would be to test it on larger, institutionally verified TBML datasets that include real laundering annotations, cross-border trade activity, and changing fraud patterns. That would make the framework more reliable in situations that look closer to actual banking operations.

Future work could also add transformer-based document understanding so the system can read unstructured trade records such as invoices, customs declarations, shipping documents, and letters of credit more effectively. Those semantic features could be combined with the graph-learning pipeline to improve document verification and anomaly detection. The federated setup could also be widened to cover more geographically distributed institutions and a larger decentralized training network.

Another worthwhile direction is stronger privacy protection during federated training. Techniques such as Fully Homomorphic Encryption (FHE), Secure Multi-Party Computation (SMPC), and differential privacy could reduce the risk of gradient leakage and model-inversion attacks. It may also be useful to study Continuous-Time Dynamic Graph (CTDG) models and explainable graph neural networks to improve temporal tracking and make the model easier for compliance teams to interpret.

In the long run, the framework could evolve into a broader banking compliance platform instead of remaining only a detection system. That would allow features such as transaction freezing, adaptive risk-trigger handling, document verification, regulator-approved intervention workflows, and policy-based account restrictions to be connected more directly with core banking systems.
