\chapter{Software Requirements Specifications  of the Proposed TBML Detection Framework}
% ========================================================

The software requirements specifications of the proposed TBML detection framework define the operational functionalities, performance expectations, software dependencies, and computational resources required for efficient execution of the system. These specifications ensure that the framework can support real-time fraud analysis, scalable transaction monitoring, secure user interaction, and intelligent compliance management within financial institutions. The detailed software requirements are categorized into functional requirements, non-functional requirements, software dependencies, and hardware requirements as described in the following subsections.
%========================================================
\section[Overall Description]{\textbf{Overall Description}}
%========================================================

The proposed framework is designed as a privacy-preserving financial monitoring platform for identifying suspicious Trade-Based Money Laundering activities across large-scale transactional ecosystems. The system integrates heterogeneous graph-learning mechanisms, federated analytical workflows, role-based monitoring dashboards, and automated Suspicious Transaction Report (STR) generation within a centralized compliance-monitoring environment. The framework supports real-time transaction monitoring, graph-based fraud classification, institutional investigation workflows, and regulator-side analytical visualization for detecting hidden laundering relationships across interconnected financial networks.

%========================================================
\subsection[Product Perspective]{\textbf{Product Perspective}}
%========================================================
The TBML detection framework is proposed as an intelligent financial monitoring and fraud analysis platform where machine learning based anomaly detection system can be integrated along with interactive compliance monitoring system. The architecture is a unified system environment that integrates heterogeneous graph representation, Graph Neural Network-based analytical models, federated learning mechanisms and modern web-based visualization technologies.

The system uses graphs of financial entities, such as accounts, organizations, invoices, and transactions, to represent them in a relational way. Fraud detection modules process these relationships and uncover hidden laundering patterns and relationships of suspicious transactions that are hard to spot through traditional rule-based Anti-Money Laundering systems. The framework also incorporates dashboards based on roles for financial institutions to monitor transactions, visualise fraud, manage alerts and report compliance automatically.

%========================================================
\subsection[Product Functions]{\textbf{Product Functions}}
%========================================================

The main functions offered by the proposed framework are listed below:

\begin{itemize}
\item \textbf{Financial transaction monitoring:} Monitor and review transactions and trading activity to detect suspicious behavior across large-scale financial ecosystems.

\item \textbf{Graph-based financial analysis:} Represent accounts, organizations, invoices, and transactions as interconnected graph structures to support relational analysis and reveal hidden dependencies.

\item \textbf{Fraud classification and risk prediction:} Classify suspicious transactions and produce fraud-risk scores using Graph Neural Network-based analytical models that leverage transactional relationships and behavioral patterns.

\item \textbf{Federated learning support:} Enable collaborative model training across multiple institutions while preserving data privacy, allowing model improvement without sharing raw transactional data.

\item \textbf{Real-time dashboard visualization:} Provide interactive dashboards for transaction analytics, fraud alerts, risk distributions, and investigation workflows for compliance analysts.

\item \textbf{Suspicious Transaction Report (STR) generation:} Automatically generate structured STRs for escalated cases to support regulatory reporting and compliance workflows.

\item \textbf{Authentication and role-based access control:} Enforce secure authentication and role-based privileges to protect sensitive information and control user actions within the monitoring platform.

\end{itemize}
